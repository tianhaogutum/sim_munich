# Localization

The finished date modules support Chinese (`zh`), English (`en`) and German (`de`).
`project/src/date_i18n.mjs` is a shared ES module with no DOM or Three.js dependency.
There is no build step. Each `date_i18n_<locale>.mjs` exports a plain nested object.
There are **403 string keys per locale**, including 80 ambient lines, eight three-paragraph
memories, nine achievements, and preparation for the pending story/photo/HUD work.

## Runtime API

```js
import { t, plural, getLocale, setLocale, onLocaleChange } from './date_i18n.mjs';

label.textContent = t('map.objectiveDistance', { place: t('map.places.entrance'), distance: 42 });
label.textContent = plural('hud.memoryCount', 2);
setLocale('de');
const unsubscribeLocale = onLocaleChange((locale, previous) => render());
// During disposal:
unsubscribeLocale();
```

- `detectLocale({ search?, storage?, language? } = {})` resolves a supported URL
  `?lang=` first, then localStorage `lmu-date-locale`, then navigator language, then
  Chinese. Unsupported values fall through. Regional tags such as `de-AT`, `en-GB`
  and `zh-CN` normalize to their supported base language. Storage errors are safe.
- Browser imports initialize from `detectLocale()`. Imports without a browser
  location initialize in Chinese, preserving the authored baseline in Node/tests.
  `detectLocale` remains independently testable with injected inputs.
- `setLocale(code)` validates/normalizes, persists the preference, and synchronously
  notifies listeners only when the language changes. It returns the active code.
  It does not navigate, reload, reset progress, or rewrite a `?lang=` URL. Therefore
  an explicit URL language still wins over a saved preference on the next load.
- `t(key, params)` interpolates `{name}` placeholders without evaluating replacement
  text. Unprovided placeholders stay visible. Missing values fall back to Chinese;
  completely unknown keys return the key. `setI18nDebug(true)` enables one
  `console.warn` per missing key for that module instance; production is quiet.
- `plural(key, count, params)` chooses an `Intl.PluralRules` category such as
  `key.one` or `key.other`, then interpolates `{count}`. Supply `other` in every
  locale, including Chinese. Store numbers/IDs in state, never translated text.
- The title controller updates `document.documentElement.lang` (`zh-CN`, `en`, `de`)
  initially and on changes. It provides the language control under Settings on
  both the title and pause screens. Other modules do not mutate shared page DOM.

Most strings are plain text. A few title/free-camera strings contain authored
`<br>` markup. Only insert trusted dictionary markup into HTML; use `textContent`
for dialogue, names, user data, and interpolated values. `t()` itself does not HTML-escape.

## Adding copy or a locale

1. Add a stable, namespaced key to **all three** dictionaries. Keys describe purpose
   (`title.start`), not the current translated sentence. For a new locale, add its
   dictionary import, register it in `dictionaries` and `locales`, and provide its
   native language name under `title.locales.<code>` in every dictionary.
2. Preserve the same placeholder names and all plural variant keys. Translate whole
   phrases rather than concatenating fragments in language-specific word order.
3. Use `t()` when rendering. For UI rendered once, subscribe to `onLocaleChange` and
   rerender or update its text/ARIA labels. Release subscriptions during disposal.
   Preserve the current modal, page, focus, and gameplay state while rerendering.
4. Do not cache a translated value in top-level constants. The banter, memory and
   cinematic data exports retain their existing shapes using getters, so reads
   resolve the current language. Copying them with object spread snapshots text;
   read their getters again when language changes.
5. Use `speakers.player` / `speakers.companion` for display names. Their defaults are
   我 / TA, Me / Him, and Ich / Er. Change those dictionary values to configured
   personal names without changing the `player` / `companion` role IDs. Existing
   external `banter.say(who, text)` calls are literal text by contract; callers own
   translation of that supplied text. Internally authored queued/active banter
   retranslates on a locale change while retaining timing and cooldown IDs.
6. Keep the restrained memorial register, natural English, and informal German
   du-Form. Proper place names stay intact; German uses umlauts and “Brezn” where
   appropriate. Do not derive save keys from any displayed name.
7. Run `node --test project/tests/*.test.mjs`. The localization suite checks exact
   key parity, matching placeholders, fallback, detection priority, safe persistence,
   subscriptions, plurals, static lookup references and live data getters.

## Pending module integration

These files were deliberately **not edited**: `anime_main.js`, `date_route.mjs`,
`date_story.mjs`, `date_story_ui.js`, `date_story.css`, `date_cast.js`, `date_photo.js`,
`date_photo.css`, `index.html`, and `DATE_CONTRACT.md`. Their existing visible text
can therefore remain Chinese until their owners wire these prepared keys.

| Owner / surface | Prepared dictionary keys | Wiring |
| --- | --- | --- |
| Story objectives | `story.objectives.<stage>`, `story.objectives.photosProgress` | Resolve inside `objectiveFor(state)`; photos use `{count, total}`. Keep `{text, poi}` and all reducer IDs unchanged. |
| Story prompt, dialogue controls | `story.taskPlace`, `story.continue`, `story.choose`, `story.close`, `story.restart`, `speakers.*` | Resolve in `promptFor`/render and rerender the current dialogue on locale changes. New authored dialogue/choices still need their own keys once finalized. |
| Ending copy | `story.postcardTitle`, `story.postcardBody` | Resolve inside `postcardText(state)`. Add separate keys for any choice-sensitive endings once authored. |
| Photo overlay / album | `photo.hint`, `photo.save`, `photo.shutter`, `photo.close`, `photo.album`, `photo.empty`, `photo.postcard`, `photo.export`, `photo.saved` | Update existing overlay controls and album labels on language changes. Draw canvas export text at capture time, with the current locale. |
| Photo targets / failures | `photo.facade`, `photo.fountain`, `photo.couple`, `photo.moveCloser`, `photo.moveBack`, `photo.center`, `photo.occluded` | Match stable target IDs. These failure keys are prepared wording for the future real validation path, not new validation behavior. |
| Shared page / HUD | `hud.documentTitle`, `hud.title`, `hud.move`, `hud.run`, `hud.mouseDrag`, `hud.rotate`, `hud.wheel`, `hud.zoom`, `hud.interact`, `hud.photo`, `hud.days`, `hud.popupDays`, `hud.close`, `hud.sakura`, `hud.plaque` | Entry-owned render updates `document.title` and existing nodes. Days use `{days}`. Preserve any nested nodes whose IDs the entry still queries. |
| Sightseeing cards | `hud.sights.<poi>.name`, `.text`, `.source` | Resolve at panel display time and when locale changes while open. These translate current authored descriptions, without adding or verifying historical claims. |
| Route / place labels | `map.places.<poi>`, `map.objectives.<poi>`, `photo.<targetId>` | Resolve presentation labels at render time. Do not change coordinates or IDs. The finished minimap already uses the map keys without mutating route data. |

A minimal UI recipe is:

```js
function render() {
  const state = story.getState();
  objective.textContent = objectiveFor(state).text;
  // Render the same current dialogue/album/page; do not dispatch a story event.
}
const unsubscribeStory = story.subscribe(render);
const unsubscribeLocale = onLocaleChange(render);
render();
// dispose(): unsubscribeStory(); unsubscribeLocale();
```

The title's pause objective is already translated using the prepared story keys.
The full HUD still depends on the story/entry owners applying the recipe above.
The ambient-life module `lmu_life.js` contains mesh/debug names but no player-facing
text, so it needs no localization changes.
